[ ] H1 (ALTA) - Porta 9090 em HTTP puro exposta na internet
------------------------------------------------------------------------
Problema: http://45.56.77.43:9090 responde sem TLS. O DESKTOP fala com a
API por esse endereco (texto plano), entao login (email+senha) e o sync
dos 48k clientes (nome/CPF/RG/telefone/email) trafegam sem criptografia -
qualquer um no caminho da rede consegue capturar (MITM/sniffing).

Como corrigir (a ORDEM importa, senao o desktop para de funcionar):
  [x] 1. AppSettings.cs alterado para https://api.clinicaideia.com.br
         (17/07/2026, compilado OK).
  [ ] 2. Recompilar e distribuir o desktop atualizado (updater) a TODAS as
         maquinas que usam o sistema.
  [ ] 3. So depois, na VM, fechar a 9090 para o mundo externo:
           ufw delete allow 9090/tcp && ufw reload
         (o nginx continua usando 127.0.0.1:9090 internamente, sem problema)

[ ] M3 (MEDIA) - "Acesso exclusivo da diretoria" e so no cliente
------------------------------------------------------------------------
Problema: VITE_ALLOWED_EMAILS rodava no navegador (cosmetico). Qualquer conta
valida e confirmada chama a API direto e ve os dados da propria empresa.
Nao vaza dados de OUTRA empresa (isolamento por empresa esta correto), mas
a "exclusividade" nao existe no servidor.

08/08/2026: a allowlist do front foi REMOVIDA. Alem de cosmetica, ela ficava
compilada no bundle e barrava a conta clinica.ideia@gmail.com em aparelhos com
build antigo em cache ("Este acesso e exclusivo da diretoria"). Agora quem
autoriza e a API. Se exclusividade voltar a ser requisito, implementar no
servidor (abaixo) — nunca no front.

Como corrigir (se exclusividade for requisito real): validar no servidor,
ex. exigir PERFIL='Administrador' nos controllers do portal, ou allowlist
de email no appsettings (NAO no bundle do front).


========================================================================
 O QUE JA ESTA BLINDADO (auditado e aprovado - nao precisa mexer)
========================================================================
- Sem secrets no bundle do app (so a URL publica da API).
- IDOR/BOLA contido: empresaId vem sempre do token, nunca do payload.
- SQL Injection: todas as queries parametrizadas; nomes de tabela/coluna
  vem de whitelist.
- Senhas: PBKDF2-SHA256, 210.000 iteracoes, salt aleatorio, tempo constante.
- Tokens de sessao: 384 bits aleatorios, guardados hasheados (SHA-256) no
  banco, expiram em 12h, revogados no reset de senha.
- Anti-enumeracao no recuperar-senha.
